# Учебный журнал

Этот файл хранит рабочую точку продолжения и подтверждённые предпочтения. Он не заменяет конспект и не должен содержать полные решения задач.

## Где остановились

- Зорич, том 1, глава II, § 2, п. 3, «Принцип Архимеда» (печатные страницы 79–81): разобрана цепочка доказательства через супремум, ограниченные подмножества N и Z, минимальный элемент и формулировка Архимеда; перечислены следствия 7°–10°.
- По просьбе пользователя прежние SVG-чертежи удалены; в `Diagrams/` остался только `следствие-9-логика-доказательства.svg` (пример a=1,4, b=2,1, n=2, m=3, r=3/2; акцент на цепочке a < r ≤ a + 1/n < b).
- Следующий шаг: при вопросах о следствии 9 объяснять, как из 1/n < b−a и (m−1)/n ≤ a < m/n выводится a < m/n < b.

## Предпочтения и стиль мышления

- Основной формат работы — вопросы по ходу доказательств и разбор непонятных переходов.
- Ассистенту следует самому задавать уместные наводящие вопросы, чтобы помогать пользователю самостоятельно увидеть следующий шаг; вопросы должны опираться на определения и обсуждаемые учебники.
- Если пользователь спрашивает о конкретной теореме или принципе из названной книги, сначала сверить формулировку и ход доказательства с PDF; отдельно обозначать, если приводится равносильная формулировка или альтернативное доказательство.
- Пользователь может присылать фотографии непонятных фрагментов; распознавать, находить и сверять место по PDF Зорича перед объяснением, а для логики доказательства использовать также Вельмана.
- Для анализа основная опора — Зорич, тома 1 и 2.
- Объяснять доказательства и по математическому содержанию/контексту Зорича, и подробнее разбирать логику и стратегию по Вельману: показывать форму цели, выбор метода и соответствие шагов доказательства этому методу.
- Вельмана использовать систематически как подробный каркас: анализировать форму цели и предпосылок, выбирать относящуюся к ней стратегию по главе 3 и пояснять, как она превращается в план и шаги доказательства. Одного называния метода недостаточно.
- Графики функций в GeoGebra пользователь строит самостоятельно; не открывать GeoGebra и не строить графики за него.
- По возможности показывать наглядные схемы отрезков, интервалов и отношений между множествами; визуальные пояснения должны помогать пониманию доказательств.
- На математических чертежах подписывать ключевые объекты прямо на рисунке; для принципа Архимеда явно отмечать точку x и показывать h как длину шага между соседними делениями.
- Для рисунка принципа Архимеда ясно показывать количество полных шагов h от 0 до x, остаток и следующий кратный; пользователь предпочитает более подробные и аккуратные досочные чертежи, не чрезмерно схематичные.
- Все математические чертежи пользователь предпочитает подробными, аккуратными, в формате SVG и построенными на конкретных примерах, с ясными подписями величин и отрезков.
- Каждый созданный чертёж сохранять отдельным SVG в `Diagrams/` проекта и давать ему описательное имя по теме/примеру на русском языке.
- Последнее уточнение пользователя: математические чертежи делать только в SVG, сохранять в `Diagrams/` с русским названием; tldraw и другие плагины для черчения не использовать, PNG не создавать.
- Вычислительную проверку на Python не использовать.
- Другие особенности стиля пока не установлены; уточнять по мере совместной работы, не делать преждевременных выводов.
